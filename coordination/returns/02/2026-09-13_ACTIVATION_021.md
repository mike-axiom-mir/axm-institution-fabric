## Uncertainties and blockers

1. Return-packet v0.3 still admits opaque strings in `artifacts_created`, `artifacts_modified`, and `evidence_refs`. This activation intentionally did not silently change that historical contract. The exact resolver is an operational precondition for future compatibility, not retroactive schema reinterpretation.
2. `artifacts_modified` is semantically under-specified for exact change identity. A truthful modification needs both the exact prior artifact instance observed/targeted and the exact produced artifact result. The current single string cannot encode both without guessing which side it names.
3. Frozen `ADV-002-C` remains active: artifact `provenance.base_state_revision` is not yet an exact immutable state-revision relationship, so it cannot be promoted into exact provenance/replay evidence.
4. Frozen `ADV-002-I` remains active: a logical modified-artifact target is insufficient for selective stale compatibility. One exact result ref alone also does not solve the missing expected-prior identity.
5. `artifact.supersedes_ref` is still an opaque string and cannot currently substitute for a fully grounded exact prior-target relationship.
6. Exact evidence identity does not itself prove that the evidence supports the right subject, has sufficient quality, or satisfies a lane requirement. Those are later compatibility semantics and remain closed.
