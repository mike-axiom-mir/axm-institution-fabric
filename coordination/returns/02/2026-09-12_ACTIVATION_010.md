## Behavior repaired

The three `base_state_revision_ref` fields now use the exact reference shape producible by the current valid `state-revision.schema.json` v0.2 contract:

```text
^axmref:v1:state-revision:[a-z0-9][a-z0-9._-]*:-:sha256:[0-9a-f]{64}$
```

Why this is the current producer language:

- state-revision logical ids are restricted by contract to `[a-z0-9][a-z0-9._-]*`;
- every allowed id byte is already RFC3986-unreserved and therefore must remain literal under Decision 003;
- state-revision v0.2 has no `version` field, so its immutable ref uses the absent-version `-` sentinel;
- the digest remains lowercase 64-hex SHA-256.

This closes the concrete `ADV-026-A` direction: a lifecycle object can no longer be contract-valid merely by embedding a `%HH` spelling such as `%2E` that `parse_immutable_ref()` rejects as noncanonical.

## Semantic nuance preserved for review

The repaired lifecycle schemas now accept the **current state-revision v0.2 producer language**, which is intentionally narrower than every syntactically parser-valid `axmref:v1:state-revision` string the generic parser could represent in isolation.

For example, the generic parser can represent percent-encoded reserved/non-ASCII components or an explicit `v=` token, but the current state-revision contract cannot produce such an immutable reference because its logical id grammar is narrower and it has no version field.

Lane 02 therefore claims the concrete dangerous mismatch is closed for references that can actually identify a valid current state-revision object. Lane 02 does **not** silently claim a new universal axmref grammar. Lane 03/Lane 01 should explicitly verify whether producer-language equivalence is the intended Decision 006 contract boundary or whether a reusable parser-backed validation primitive is required before integration.

The same broad regex family remains visible in other already-integrated exact-reference schema surfaces such as state-revision membership. This activation does not silently expand PR #15 into a repository-wide schema rewrite; that scope remains evidence-driven and should be decided separately if an actual accepted-invalid witness matters there.
