## Bounded claim

> During Decision 023 exact target validation, direct mutation of `store.__dict__["schema_dir"]` must not be able to make the actual validation operation consume a caller-owned schema interpretation and then restore visible state before the observer can detect it.

The repair keeps the already-grounded exact `FilesystemObjectStore` boundary and the existing caller-visible `load_bytes` invocation, but changes the invocation-local guard from an assignment-only `__setattr__` check to a `schema_dir` **data descriptor**. While the guard class is active:

- ordinary `schema_dir` assignment away from the function-owned snapshot fails through the descriptor setter;
- direct `store.__dict__["schema_dir"]` mutation may alter backing state, but it does not become validation interpretation authority;
- every actual `self.schema_dir` read used by `FilesystemObjectStore._verify_existing()` resolves through the descriptor getter;
- the getter returns only the function-owned `snapshot_dir` when the backing instance value still matches it;
- otherwise the getter raises `SourceLiveObservationContextError`, so validation fails closed before a different schema context can be consumed as a normal observation.

This is a repair of the demonstrated Decision 023 same-invocation coherence path.
