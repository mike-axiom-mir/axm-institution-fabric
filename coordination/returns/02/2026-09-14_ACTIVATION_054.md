## Smallest repair implemented

`axm_institution/source_live_observation.py` now extends the existing invocation-local guard with a `load_bytes` **data descriptor**.

Within the guarded Decision 023 target-load window:

1. the descriptor checks whether the exact store instance carries a caller-owned instance `load_bytes` shadow in `store.__dict__`;
2. if present, that caller dispatch still runs first, preserving the already-demonstrated caller-visible error behavior and the unchanged ADV-058-C/D/E oracle's proof that the shadow was actually exercised;
3. if caller dispatch raises `ObjectStoreError`, the existing Decision 023 error classification remains in force;
4. if caller dispatch returns successfully, that return is **not** accepted as validation proof;
5. the observer then calls `FilesystemObjectStore.load_bytes(self, reference, schema_name)` directly;
6. that base operation performs the actual exact-path read plus `_verify_existing()` canonical bytes / schema validation / immutable-reference reproduction checks;
7. its `schema_dir` reads still go through the existing invocation-local data descriptor and therefore remain bound to the function-owned schema snapshot or fail closed;
8. only a successful base exact-store load can reach normal `exact_observed` mapping.

For an ordinary unshadowed exact store, the descriptor calls the base exact-store loader directly once.

This repair binds the positive fact to the real existing exact-store operation without inventing persistent context identity, retained-byte authority, or wider code-isolation semantics.
