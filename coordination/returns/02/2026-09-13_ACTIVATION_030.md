## Implementation

### 1. Explicit return-packet v0.4 modified relation

`schemas/return-packet.schema.json` now accepts two explicit historical contract versions:

- **v0.3** retains the existing `artifacts_modified[]` opaque-string shape exactly as historical state;
- **v0.4** requires each `artifacts_modified[]` entry to be an object with exactly:
  - `prior_artifact_ref`
  - `result_artifact_ref`

The conditional schema makes the two forms mutually exclusive. A v0.3 packet cannot use the new object relation, and a v0.4 packet cannot use the old opaque string. Historical v0.3 is therefore not silently relabelled as exact two-sided proof.

### 2. Reusable bounded Decision 010 artifact work-base check

`axm_institution/packet_artifact_provenance.py` now exposes `preflight_exact_artifact_work_base_provenance(...)`.

It applies only the already-canonical Decision 010 invariant to one already exact-loaded artifact:

- artifact schema v0.2;
- canonical exact `provenance.base_state_revision_ref`;
- exact-load and identity verification of that state revision;
- exact equality to the named claim base;
- `producer_lane_id` equality to the exact claim-base lane logical id.

The existing created-artifact provenance preflight now delegates to this helper after its existing created-output compatibility path. No broader Decision 010 semantics were added.

### 3. Decision 011 read-only resolver

New module:

`axm_institution/packet_modified_artifact_identity.py`

New entry point:

`preflight_modified_artifact_identity(store, packet_ref)`

It:

1. requires an exact return-packet ref and exact-loads the packet;
2. reconstructs packet -> exact claim -> exact claim base -> exact claim-base lane;
3. reconstructs claim -> exact occupancy -> occupancy historical entry base -> exact entry-base lane;
4. requires only the exact snapshots' local `open` / `active` prerequisites already used by the Stage 4 preflight spine;
5. leaves any non-empty historical v0.3 modified list operationally unresolved rather than reinterpreting it;
6. for v0.4, parses both explicit refs through the shared Stage 2 immutable-reference parser and requires kind `artifact`;
7. requires the exact prior ref itself to occur in the exact claim base's `artifact_refs` family;
8. exact-loads and identity-verifies that exact prior artifact;
9. exact-loads and identity-verifies the exact result artifact;
10. applies the bounded Decision 010 work-base / producer-lane provenance check to that result against the same exact claim base and lane;
11. returns tuple-backed exact relation records and the existing canonical-byte-backed immutable JSON views;
12. performs no write or successor-state mutation.

No logical-id search, version preference, storage order, array order, newest/current state, `supersedes_ref`, actor identity, schedule position, founder status, specialist identity, or Git permission participates in endpoint selection.

## Uncertainties / truth boundary

1. A successful Decision 011 preflight proves only that both exact endpoints can be reconstructed and that the prior belongs to the exact work base while the result satisfies the already-grounded Decision 010 work-base/producer-lane condition.
2. It deliberately does **not** prove that prior and result represent the same logical artifact, that either version is newer, or that the result validly supersedes the prior.
3. `artifact.supersedes_ref` remains a generic field with no authority over the explicit packet pair.
4. Evidence, source, and dependency relations on the result remain outside this bounded identity precondition.
5. The dedicated modified-artifact preflight is separate from the older created-output identity/evidence/compatibility path. That older path remains intentionally fail-closed on any non-empty modified-artifact list; no existing created-output consumer silently acquires new modified-artifact semantics.
6. The module currently reuses package-internal exact-load/freeze primitives from `packet_output_identity.py`; this is an implementation dependency, not a new semantic authority. A future public factoring may improve structure but is not required to claim this bounded invariant.
