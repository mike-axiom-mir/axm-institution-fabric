## Behavior added / repaired

### State revision contract v0.2

The revision contract was explicitly bumped from `0.1` to `0.2` because the membership meaning is intentionally breaking rather than silently reinterpreting the old field names.

The canonical membership fields are now:

- `parent_revision_ref` — nullable exact `state-revision` immutable ref;
- `objective_ref` — exact `objective` immutable ref;
- `lane_refs` — exact `lane` immutable refs;
- `occupancy_refs` — exact `occupancy` immutable refs;
- `claim_refs` — exact `work-claim` immutable refs;
- `artifact_refs` — exact `artifact` immutable refs;
- `evidence_refs` — exact `evidence-record` immutable refs;
- `return_packet_refs` — exact `return-packet` immutable refs;
- `integration_receipt_refs` — exact `integration-receipt` immutable refs.

Array memberships remain unique. Kind-specific `axmref:v1` structure is required at the schema boundary. Logical ids remain inside referenced objects for search/navigation and are no longer treated as sufficient immutable snapshot identity.

### Decision 005 regression witnesses

`tests/test_state_revision_membership.py` adds seven direct regressions:

1. two valid objectives with the same logical id but different content receive different immutable refs;
2. substituting one objective ref for the other changes the immutable state-revision identity;
3. two lane contracts with the same logical id but different content cannot collapse to one revision membership identity;
4. a parent revision must be named by an exact `state-revision` immutable ref and a bare logical revision id fails;
5. duplicate exact refs fail for every unique membership array;
6. every revision membership field parses as the expected typed exact immutable-ref kind;
7. the legacy v0.1 logical-id membership shape is rejected by the repaired contract.

The valid contract fixture was updated only as required to validate the v0.2 state-revision shape.

### CI compile coverage repair

The existing deterministic workflow already discovered the new regression module during `unittest`, but its explicit `py_compile` command named only the earlier test files. The compile step was minimally widened to include `test_contract_schemas.py` and `test_state_revision_membership.py` so the affected test surface is explicit rather than inferred from import during test execution.
