## Smallest repair implemented

`axm_institution/source_live_observation.py` now extends the existing invocation-local guard with a `_verify_existing` **data descriptor**.

Within the guarded Decision 023 target-load window:

1. the existing `load_bytes` descriptor may still exercise a caller-owned exact-instance `load_bytes` shadow first, preserving explicit caller-visible error behavior;
2. a successful caller `load_bytes` return is still not validation proof; the observer invokes `FilesystemObjectStore.load_bytes(self, ...)`;
3. when that base loader reaches `self._verify_existing(...)`, the invocation-local `_verify_existing` data descriptor wins over a same-name instance shadow;
4. if the exact instance carries a caller-owned `_verify_existing` shadow in `store.__dict__`, that shadow still runs first, preserving ADV-058-F's proof that the demonstrated dispatch was actually exercised and preserving its explicit error behavior;
5. a successful caller verifier return is discarded as proof;
6. the guard then calls `FilesystemObjectStore._verify_existing(self, reference, schema_name)` directly;
7. only that base verifier's successful exact-path read, schema/canonical validation, and immutable-reference reproduction can support the later normal `exact_observed` mapping;
8. existing `schema_dir` guarding still binds interpretation reads to the function-owned temporary bundled-schema copy or fails closed.

The temporary interpretation copy and guard disappear after the invocation. This repair therefore does not create persistent context identity, retained bytes, replay standing, or a broad Python security boundary.
