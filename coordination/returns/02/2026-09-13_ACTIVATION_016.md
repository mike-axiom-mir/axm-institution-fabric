## Behavior implemented

`admit_occupancy(store, occupancy)` now:

1. validates the occupancy through `occupancy.schema.json` using the existing deterministic validation boundary;
2. exact-loads `base_state_revision_ref` through the immutable store as `state-revision`;
3. resolves `lane_id` only through the integrated `resolve_exact_revision_member(...)` primitive using `lane_refs` / required kind `lane` against that exact base;
4. fails before occupancy persistence if the base or selected lane relationship cannot be grounded;
5. persists the validated occupancy immutably only after the exact-base lane relationship succeeds;
6. returns `OccupancyAdmissionResult(occupancy_ref, lane_ref, created)`;
7. leaves `claim_ids` untouched as snapshot/navigation data and creates no work claim;
8. creates no successor revision and has no `current`/`HEAD` pointer behavior.

The explicit exact-base load before resolution is deliberate: occupancy admission treats the entry base as a transition prerequisite rather than relying on an incidental helper side effect. `resolve_exact_revision_member(...)` then performs its own exact base/member verification while resolving the lane family.

## Root grounding

### Truth

Admission distinguishes contract validity, exact base existence, exact lane membership, immutable occupancy persistence, and canonical successor state. Passing admission does not get renamed into successor publication or institutional currentness.

### Agency / non-domination

Lane selection is constrained to exact membership in the occupancy's named entry base. Actor identity, capability identity, newer storage entries, schedule position, founder status, Git permission, and chat state receive no hidden authority.

### Continuity

A replacement occupant can recover the admitted occupancy's exact immutable identity, exact entry base, and exact resolved lane from persisted repository/store state without private conversation history. Ambiguity and missing/corrupt dependencies fail explicitly instead of silently selecting another object.

### Wisdom before speed

The implementation stops at occupancy admission. It does not generalize into a lifecycle engine and does not pull claim opening, packet submission, successor publication, integration, epochs, or replay forward before this slice receives adversarial review.
