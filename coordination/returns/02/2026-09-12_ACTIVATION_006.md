## Behavior added / repaired

### Decision 004 canonical string rendering

Production canonical rendering no longer delegates string spelling to `json.dumps`.

A dedicated renderer now explicitly implements the accepted repository contract for both object keys and string values:

- `"` -> `\"`;
- reverse solidus -> `\\`;
- `/` remains literal;
- `U+0008/U+0009/U+000A/U+000C/U+000D` use `\b/\t/\n/\f/\r`;
- every other `U+0000..U+001F` uses lowercase-hex `\u00xx`;
- every other permitted Unicode scalar value remains literal and is encoded as UTF-8.

The parser still accepts alternate valid JSON spellings, but immutable identity is derived only from the explicit canonical spelling.

### Regression witnesses

A bounded Decision 004 test module now freezes:

- `ADV-023-A`: `a/b` canonicalizes with literal `/`, including when the input was valid JSON `a\/b`;
- literal solidus behavior for keys and values;
- quote and reverse-solidus escapes;
- all five required short control escapes;
- non-short controls `U+0000`, `U+000B`, and `U+001F`, including lowercase hex letters;
- literal UTF-8 output for `é`, `U+2028`, and `U+2029`;
- rejection of ASCII-only `\u00e9` as canonical output by direct byte comparison.

Existing Decision 003 regressions `ADV-021-A` and `ADV-022-A` remain unchanged and passing.
