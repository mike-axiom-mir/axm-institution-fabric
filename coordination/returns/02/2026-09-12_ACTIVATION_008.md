## Behavior added / repaired

### Immutable store

`FilesystemObjectStore` validates and canonicalizes an object through the existing Stage 2 implementation, derives its exact typed immutable reference, and stores only those canonical bytes.

The final object path is content-addressed by kind + SHA-256 digest. Logical id/version are not used as mutable filenames; exact reference reproduction is checked on every normal lookup.

### Atomic publication

Writes are first fsynced to a same-directory temporary file. Publication uses an atomic hard-link create that does not overwrite an existing immutable path. The temporary name is outside normal exact lookup and is removed after successful/failed publication where possible.

If an exact target already exists, the store verifies it instead of overwriting it. Corrupt existing content therefore fails loudly rather than being silently repaired or replaced.

### Exact lookup truth boundary

Normal lookup reads one byte sequence, validates/canonicalizes that same sequence, confirms the canonical bytes are byte-for-byte identical, and confirms the recomputed immutable reference equals the requested reference.

During self-review, the first implementation of `load_bytes()` verified a file and then re-read it. That introduced a verify/read race where a later byte sequence might be returned without being the one verified. This was repaired before final evidence: `_verify_existing()` now returns the exact bytes it verified, and `load_bytes()` returns those bytes directly.

### State-revision boundary

For `state-revision` writes, `StoreWriteResult.referenced_members_verified` is explicitly `False`.

This means only:

```text
revision object bytes stored under exact immutable identity
```

It does **not** mean:

```text
all named member refs resolve
revision accepted by integration
revision is current institutional state
```

## Unresolved uncertainty / blockers

1. Atomic publication currently relies on same-filesystem hard-link creation. This is tested on the GitHub Ubuntu runner but not yet reproduced on Windows/macOS or unusual filesystems. The implementation fails explicitly rather than silently using a weaker overwrite fallback if publication is unsupported.
2. The test for interrupted writes proves orphan/temp bytes are outside exact lookup and final publication is atomic in the tested environment; it does not simulate abrupt power loss at every filesystem boundary.
3. No concurrent multi-process stress test has been run. The no-overwrite link primitive and exact verification reduce the race surface, but concurrency is not yet claimed as measured behavior.
4. State-revision member refs are preserved exactly but are not resolved for closure. `referenced_members_verified=False` records that non-proof explicitly.
5. Cross-language/cross-platform Stage 2 identity reproduction remains outside this activation and remains untested.

None of these uncertainties requires pulling later institution semantics into this store slice.
