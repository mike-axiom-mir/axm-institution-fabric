## Behavior implemented

`resolve_exact_revision_member(...)` now:

1. requires a canonical immutable base reference whose kind is exactly `state-revision`;
2. accepts only the explicit state-revision membership families already present in v0.2;
3. requires the caller's requested kind to match that membership family;
4. loads the exact base revision through `FilesystemObjectStore`;
5. inspects only the exact refs named by the selected membership family;
6. loads and identity-verifies **every** exact ref in that selected family before deciding whether it matches the requested logical id;
7. requires the verified object's `id` to agree with the logical id encoded in its immutable ref;
8. returns the exact member ref plus verified object only when exactly one member has the requested logical id;
9. fails explicitly when zero or multiple exact instances match;
10. propagates missing-member and corrupt-member store failures rather than silently skipping them;
11. does not select by array position, newest version, recency, mutable current/HEAD, actor identity, schedule position, or hidden chat state.

The selected family is verified for the attempted resolution, but this does **not** mark the entire revision referentially complete. `StoreWriteResult.referenced_members_verified=False` remains unchanged for state revisions.
