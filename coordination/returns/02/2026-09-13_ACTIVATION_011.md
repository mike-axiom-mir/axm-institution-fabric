## Repair implemented

### ADV-028-A — state-revision producer true-end semantics

The state-revision `id` pattern changed only at its end condition:

```text
before: ^[a-z0-9][a-z0-9._-]*$
after:  ^[a-z0-9][a-z0-9._-]*(?![\s\S])
```

`(?![\s\S])` succeeds only when there is no remaining character. It therefore does not inherit Python `$` behavior that may match immediately before one final LF.

This keeps the already-established state-revision logical-id alphabet unchanged while making the intended end boundary explicit.

### ADV-028-B — lifecycle exact-base true-end semantics

The three Decision 006 fields now use:

```text
^axmref:v1:state-revision:[a-z0-9][a-z0-9._-]*:-:sha256:[0-9a-f]{64}(?![\s\S])
```

Affected fields:

- `occupancy.base_state_revision_ref`
- `work-claim.base_state_revision_ref`
- `return-packet.base_state_revision_ref`

No mutable/latest/current lookup was introduced. The exact kind remains `state-revision`; the v0.2 migration, bare-logical-id rejection, wrong-kind rejection, legacy-field rejection, same-logical-revision/different-instance identity behavior, and exhaustive percent-encoded-unreserved rejection remain intact.

### Why this is narrow

No Stage 2 parser code changed. The repair aligns the affected contracts with the already-canonical parser semantics instead of creating a second identity mechanism.

Other repository regexes using `$` were not mass-rewritten. Their possible final-LF behavior remains an explicit separate audit question rather than being silently bundled into Decision 006.
