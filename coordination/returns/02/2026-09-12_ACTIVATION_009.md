## Behavior added / repaired

### 1. Exact lifecycle bases are now machine-constrained

All three lifecycle schemas move from `0.1` to `0.2` and replace the ambiguous field:

`base_state_revision`

with the visibly exact field:

`base_state_revision_ref`

The value must match the canonical typed form:

`axmref:v1:state-revision:<logical-id>:<version-slot>:sha256:<64-lowercase-hex>`

A bare revision id, an objective/artifact/other-kind ref, a malformed ref, or the old field name cannot satisfy the repaired contracts.

### 2. Existing lifecycle semantics were preserved narrowly

The repair intentionally leaves lane ids, claim ids, occupancy ids, actor/capability refs, scope refs, overlap fields, occupancy lifecycle status/time constraints, return-packet evidence, uncertainty, blocker, downstream-effect, and follow-up fields in place.

No compatibility fallback accepts the old v0.1 base field under the v0.2 schema.

### 3. Decision 006 identity witness is executable

`tests/test_lifecycle_base_refs.py` constructs two valid state revisions with the same logical revision id but different canonical content. The integrated Stage 2 identity path produces two different immutable state-revision refs.

Substituting those exact refs into otherwise identical:

- occupancy objects;
- work-claim objects;
- return-packet objects;

changes each lifecycle object's immutable identity.

This proves the base relationship is part of the exact object meaning rather than a display-only label.

### 4. ADV-002-D/E/F rejection witnesses are explicit

The invalid contract fixture now contains paired witnesses for each repaired relationship:

- bare logical revision id rejected;
- wrong-kind immutable ref rejected.

Existing occupancy lifecycle counterexamples were updated to v0.2 exact-base syntax so they continue testing their intended status/time failures rather than passing merely because they contain a stale base field.
