## Behavior added

### Strict canonical input boundary

The parser rejects ambiguous or non-portable v0 inputs instead of silently rewriting their meaning:

- duplicate JSON object keys;
- floating-point JSON numbers;
- non-canonical integer spelling such as `-0`;
- integers outside the cross-runtime safe range;
- `NaN` / `Infinity` constants;
- non-NFC Unicode text;
- surrogate code points;
- unsupported runtime value types.

Supported canonical values use deterministic sorted-key, compact, UTF-8 JSON. Schema defaults are not silently inserted. Omitted optional fields therefore remain distinct from explicitly present default-valued fields at the content-identity layer.

### Stage 1 contract validation

The identity module can load any named integrated `*.schema.json`, validate an object with Draft 2020-12 + format checking, and emit a useful first validation location on failure.

### Reproducible immutable identity

Validated instance identity is SHA-256 over canonical validated bytes. Logical `id` remains visible but is not treated as immutable identity.

### Explicit reference encoding

The implementation uses:

```text
axmref:v1:<kind>:<logical-id>:<version-token>:sha256:<64-lowercase-hex>
```

Components are canonically percent-encoded when needed. A missing object version uses `-`; a present version uses `v=<encoded-version>` so a real `-` version cannot collide with the sentinel. Parser and resolver reject malformed/non-canonical forms and require exactly one matching candidate instance.

### `ADV-015-B` exact evidence binding

A fixture contains `artifact.rules` version 1 and version 2. Strong `automated_tested` evidence is constructed against the immutable reference for version 1. Validation succeeds for version 1 and fails when the same evidence is presented as support for version 2 despite the shared logical id.

This closes the **identity-layer** form of `ADV-015-B`; it does not claim repository-wide evidence graph validation exists yet.

## Unresolved uncertainty / review targets

1. **No silent default insertion.** JSON Schema defaults remain annotations. Two otherwise equivalent objects where one explicitly includes an optional default and one omits it hash differently. This follows the current no-silent-normalization rule, but Lane 03 should adversarially challenge whether any Stage 1 field requires stronger semantic equivalence.
2. **Numeric subset.** V0 rejects floats and restricts integers to the common exact cross-runtime range. Current Stage 1 institution objects do not require numeric instance fields; if a later universal contract requires fractional or larger numeric values, canonical numeric semantics must be chosen explicitly rather than relaxed silently.
3. **Reference encoding is reviewable, not self-canonizing.** `axmref:v1` is the Lane 02 implementation choice permitted by Decision 002. It should remain proposed through the PR until Lane 03 challenge and Lane 01/root-grounded review.
4. `ADV-002-B`, `ADV-011-B`, and `ADV-006-B` deliberately remain later cross-object/state obligations; this module only supplies exact identities for those validators to consume.
