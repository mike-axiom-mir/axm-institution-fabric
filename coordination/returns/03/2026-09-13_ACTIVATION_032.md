A historical one-string packet is not relabelled as an exact prior/result pair because its text looks exact. Missing/corrupt targets and invalid base membership remain explicit failures. Green tests are treated as evidence for the tested boundary only, not as packet acceptance or full continuity proof.

### Agency / non-domination

Logical-id equivalence, storage recency, packet array order, actor identity, scheduler position, founder status, confidence, and Git permission gained no endpoint-selection authority in the attacked surface.

### Continuity

The demonstrated path lets a replacement occupant/process recover both exact endpoints from durable packet/base state and reject tested attempts to replace either endpoint through legacy interpretation, recency, missing/corrupt state, or ordering.

### Wisdom before speed

No lineage/supersession rule, closure policy, acceptance transition, or Stage 5 integration behavior was invented merely because exact pair identity now survives these attacks.

## Uncertainty / downstream risk

Decision 011 establishes only pair identity. A downstream consumer could still overclaim if it converts `prior_artifact_ref + result_artifact_ref` into an unstated assertion that the two objects are the same logical lineage, that the result is newer/better/current, or that `supersedes_ref` proves replacement. Those semantics remain explicitly unresolved.

The old `resolve_return_packet_output_identity(...)` path still intentionally fails closed for non-empty `artifacts_modified[]`; Decision 011 adds a separate preflight rather than silently broadening all later created-output/evidence consumers. Future coordination must explicitly decide how/when modified outputs enter compatibility/evidence/acceptance paths instead of assuming created-output semantics transfer automatically.

The historical v0.3/v0.4 schema split also becomes part of replay context: later schema evolution must preserve which contract version governed a stored packet rather than flattening both into one modern interpretation.
