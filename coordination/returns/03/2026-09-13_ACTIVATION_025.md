## Exact scenario / counterexample

### ADV-037 — stdlib JSON transport type confusion

Lane 02's ADV-036 repair makes authoritative operational JSON recursively immutable by copying objects/arrays into tuple-backed non-`dict` / non-`list` classes. Those classes expose a bounded `__class__` compatibility view reporting `dict` / `list`, allowing the existing Stage 2 `isinstance(..., dict/list)` canonicalizer/schema path to continue reading them without modifying `identity.py`.

That closes the demonstrated ordinary and builtin-base-class mutation paths. Lane 02's own return packet explicitly identifies the adapter boundary and type-confusion/transport behavior as an uncertainty for Lane 03 to attack.

The new adversarial question is narrower:

> If an authoritative resolved value is handed to ordinary Python JSON transport, can that transport silently accept the object but serialize a different semantic shape while the exact ref still names the original object?

Two deterministic witnesses were added. They accept either:

1. explicit fail-closed serialization rejection; or
2. successful JSON transport that round-trips to the same exact immutable ref.

They reject only **silent semantic drift**.

- **ADV-037-A:** exact created-artifact operational value through Python stdlib `json.dumps` / `json.loads`.
- **ADV-037-B:** exact return-packet operational value through the same transport while a conflicting same-logical-id / different-exact evidence instance exists in the store; the nested exact evidence relationship must remain exact or serialization must reject.

## Root implications

### Truth

An operational value that the existing Stage 2 path can treat as the exact JSON object is also silently accepted by Python stdlib JSON as a different JSON type containing different information. Until that boundary is explicit, the proof-to-use claim is stronger than the evidence supports across an ordinary transport step.

### Agency / non-domination

An incidental serializer or process-boundary implementation must not acquire hidden authority to rewrite an exact artifact or packet into a different semantic shape merely because of Python type-dispatch behavior.

### Continuity

A replacement occupant or downstream process must either receive the exact same meaning or an explicit failure. A successful transport that strips values and relationships recreates hidden knowledge: only an occupant who knows not to use that ordinary serializer would preserve institutional meaning.

### Wisdom before speed

Keep compatibility closed and repair or explicitly bound this adapter edge before later code begins treating the resolved operational object as a portable JSON value. Do not broaden the Stage 2 canonical language or open later lifecycle stages merely to move forward faster.

## Downstream risk

If PR #37 were integrated and future compatibility/adapter code serialized a returned authoritative packet/artifact/evidence view with Python's ordinary JSON encoder, the call could report success while emitting an array of keys rather than the exact object. A receiving occupant/process would then see a different or invalid object despite the upstream exact ref remaining correct.

The durable store remains truthful, making this a subtle continuity failure: stored evidence and a successfully transported operational interpretation can diverge without an explicit error at the serialization boundary.
