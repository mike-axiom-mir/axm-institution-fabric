## Observed source findings

### 1. All nine exact-member families enter one semantic validation path

`identity.py` defines one `_STATE_REVISION_MEMBER_KINDS` table covering:

- `parent_revision_ref -> state-revision`;
- `objective_ref -> objective`;
- `lane_refs[] -> lane`;
- `occupancy_refs[] -> occupancy`;
- `claim_refs[] -> work-claim`;
- `artifact_refs[] -> artifact`;
- `evidence_refs[] -> evidence-record`;
- `return_packet_refs[] -> return-packet`;
- `integration_receipt_refs[] -> integration-receipt`.

After ordinary JSON-Schema validation, `validate_instance(..., "state-revision.schema.json")` invokes `_validate_state_revision_member_refs()`.

Each non-null member is then passed unchanged to the already-integrated Stage 2 `parse_immutable_ref()` and the parsed kind is compared with the field-required kind.

This closes the specific architectural failure from Activation 013: the regex is no longer being asked to duplicate UTF-8/NFC/canonical reference semantics.

### 2. The shared parser enforces the semantics required by the active gate

The inspected Stage 2 parser:

- requires the exact seven-part `axmref:v1` form;
- restricts reference kinds to the canonical kind alphabet;
- decodes percent bytes with uppercase hex spelling;
- treats raw ASCII as valid only for RFC3986-unreserved bytes;
- strictly decodes UTF-8;
- rejects non-NFC text and surrogate code points through the canonical subset check;
- re-encodes each decoded component and requires byte-for-byte spelling equality;
- rejects empty logical-id/version components;
- requires lowercase 64-hex SHA-256 spelling;
- reconstructs the complete reference and requires exact round-trip equality.

Therefore, after the PR #19 semantic pass, a member accepted by kernel state-revision validation cannot remain accepted merely because a looser regex tolerated a spelling that Stage 2 would reinterpret or reject.

### 3. Store publication uses the same validation path

`FilesystemObjectStore.store()` first calls `canonical_validated_bytes(value, schema_name, ...)`, which calls `validate_instance()`. For `state-revision.schema.json`, that now includes the shared member semantic pass before a target object is published.

The store continues to return `referenced_members_verified=False` for state-revision writes. That is correct evidence precision for this slice: semantic parser-canonicality is checked; referenced-object existence/closure is still explicitly unverified.
