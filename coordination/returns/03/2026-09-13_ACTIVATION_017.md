## Failure surface / exact counterexample

### ADV-032-A — occupancy admission proof-to-write aliasing

The current implementation performs this sequence:

```text
caller-owned occupancy mapping O
    -> validate_instance(O)
    -> validated is O itself
    -> exact-load O.base_state_revision_ref
    -> resolve exact lane using O.lane_id
    -> store(O)
    -> return stored occupancy ref + previously resolved lane ref
```

`validate_instance(...)` validates but returns the same mapping object supplied by the caller. `admit_occupancy(...)` then uses that mapping for relationship grounding and later passes it to `FilesystemObjectStore.store(...)` for canonical persistence.

Lane 03 added a deterministic probe store that changes only the caller-owned occupancy's `lane_id` at the final occupancy write boundary, after the base/lane relationship has already been grounded and immediately before the real immutable store serializes the object.

The witness avoids scheduler/thread timing as a source of ambiguity. It asks one invariant only:

```text
if admission returns success,
then the persisted occupancy must still encode the lane relationship that admission grounded,
and the returned lane_ref must be reconstructable from that persisted occupancy + its exact base.
```

A future repair is allowed either to reject the mutation explicitly or to succeed using a function-owned frozen candidate. It is not allowed to return success while persisting a different relationship.

## Why this breaks the institutional hypothesis

A replacement occupant that receives only durable repository/store state can load the admitted occupancy and see its persisted `base_state_revision_ref` and `lane_id`. Under the failing witness, that durable object no longer reconstructs the `lane_ref` that `admit_occupancy(...)` returned as the relationship it grounded.

So the transition has two incompatible truths:

```text
returned admission result -> lane-02 was grounded
persisted occupancy       -> lane-decoy is authoritative lane_id
```

Recovering which relation was actually approved would require transient execution knowledge rather than durable institutional state. That is exactly the hidden-state dependence this repository is meant to remove.

## Root implications

### Truth

A successful transition must not claim it grounded relationship A while durable state records relationship B. Proof and publication must bind the same exact candidate.

### Agency / non-domination

Caller mutation or write timing must not silently acquire authority to change the lane relationship after the deterministic admission checks have already selected and verified it.

### Continuity

A later occupant must be able to reconstruct the admitted relationship from the exact persisted occupancy and its exact base without needing transient process history or private chat. ADV-032-A currently violates that property.

### Wisdom before speed

The correct response is one narrow repair to occupancy admission, not opening the next lifecycle stages or creating a generic locking/concurrency framework before this invariant is closed.
