## Bounded adversarial failure surface

Decision 023 says a supported exact source observation may use only the exact `FilesystemObjectStore.load_bytes(target_object_ref)` path under one function-owned interpretation context, and `exact_observed` means the exact target path was read, bytes were obtained, and those bytes passed the exact-store validation/identity reproduction checks.

The repaired implementation still performs the target operation through:

`store.load_bytes(capability.target_object_ref)`

on the caller-supplied exact store instance, and it does not independently consume or verify the returned byte value before mapping a no-error call to `exact_observed`.

Prior ADV-058-C/D already established that the accepted exact store instance can carry a caller-owned instance-level `load_bytes` shadow. The D repair prevents that shadow from silently changing the schema interpretation consumed by the base verifier, but it does not establish that the shadow actually invokes the base verifier at all.
