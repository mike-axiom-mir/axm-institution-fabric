## Root implications

### Truth

Exact object existence is not the same evidence as successful lifecycle relationship admission. The transition currently collapses those two states for `occupancy_ref` operational use.

### Agency / non-domination

A generic store write must not silently acquire the semantic authority of the occupancy-admission transition. Otherwise call path and hidden convention become an undeclared authority source.

### Continuity

A replacement occupant should be able to reconstruct why an occupancy relation was accepted from durable state and deterministic rules, not assume that every stored `active` occupancy must have passed one historical function call. Re-grounding the exact entry relation at operational use removes that hidden-history dependency.

### Wisdom before speed

The contradiction appears at the first work-claim transition. Repair this bounded relationship proof before opening return submission or broader work-ledger semantics.

## Recommended bounded repair

Do not require occupancy entry base to equal claim base.

After exact-loading `occupancy_ref`, re-establish only the exact occupancy relationship already defined by canonical occupancy admission:

```text
occupancy = exact-load occupancy_ref
-> exact-load occupancy.base_state_revision_ref as state-revision
-> resolve occupancy.lane_id exactly once from that entry base's lane_refs
-> retain existing claim/occupancy logical lane equality check
-> retain local active-snapshot check if Lane 01 keeps that prerequisite
-> persist the already-detached exact claim candidate
```

A small read-only helper shared with `admit_occupancy(...)` may reduce duplication, but work-claim admission should not call a mutating admission routine merely to prove the relation.

This repair preserves Decision 007 chronology: the occupancy may have been created from an earlier base and the claim may use a later base. The repair verifies each relationship against its own exact historical base rather than forcing false base equality.

## Downstream risk if left unresolved

A SHA-valid, schema-valid, locally `active` occupancy inserted through the generic object store can currently become the authoritative exact target of a successful work claim even when:

- its own entry base is absent; or
- its own entry base makes its lane relationship ambiguous.

That creates a hidden semantic dependency on how an immutable object entered storage, which directly weakens occupant replacement and replayable continuity.
