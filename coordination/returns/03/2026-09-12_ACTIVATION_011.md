## Concrete failures found

### ADV-028-A — valid current state-revision producer can emit a ref rejected by all three lifecycle contracts

The integrated `state-revision.schema.json` constrains `id` with:

```text
^[a-z0-9][a-z0-9._-]*$
```

The integrated validator uses Python `jsonschema.Draft202012Validator`. Under Python regex semantics, `$` may match immediately before one final LF. Therefore this logical id is accepted by the current schema validator:

```text
revision.fixture.0001\n
```

The Stage 2 canonical subset does not forbid LF inside strings. The immutable-reference encoder therefore canonically percent-encodes the LF as `%0A`, producing an exact state-revision reference of the form:

```text
axmref:v1:state-revision:revision.fixture.0001%0A:-:sha256:<digest>
```

A bounded reproduction using the exact current fixture content, current canonical renderer/encoding semantics, Python 3.13.5 and the same `jsonschema 4.26.0` package produced:

```text
axmref:v1:state-revision:revision.fixture.0001%0A:-:sha256:03e0a8c117c040a3abed7b0015c798ff20ea62e8387f78cf1f0c4e70cf4931b3
```

Observed result:

- current state-revision schema validation: **accepted**;
- canonical `%0A` immutable-reference component: **accepted by Stage 2 parser semantics**;
- PR #15 occupancy base contract: **rejected**;
- PR #15 work-claim base contract: **rejected**;
- PR #15 return-packet base contract: **rejected**.

This directly falsifies the current test's sampled claim that the lifecycle pattern matches references produced by valid current state revisions. The sample id `revision.a_b-c0` passes, but the current validator admits a larger producer set because of Python `$` semantics.

### ADV-028-B — lifecycle schema accepts a parser-invalid exact-base string with one final LF

The three repaired lifecycle fields use:

```text
^axmref:v1:state-revision:[a-z0-9][a-z0-9._-]*:-:sha256:[0-9a-f]{64}$
```

With Python `jsonschema 4.26.0`, a canonical-looking exact ref followed by one final LF satisfies that pattern because `$` matches before the final LF.

The Stage 2 parser rejects the same string because the digest component contains the LF and `_DIGEST_RE.fullmatch()` fails.

Observed result:

```text

parse_immutable_ref: rejected
```

So schema acceptance is still wider than the canonical parser language after the `%2E` repair.
