## Lead interpretation / integration decision

ADV-041 is accepted as real evidence, but it marks a different boundary from ADV-035 through ADV-040.

The earlier regressions exercised returned data/result mutation and transport surfaces. ADV-041 mutates the **kernel program's class metadata itself**. Code with that authority can likewise monkeypatch resolver functions, store methods, parsers, or module globals. Continuing to swap Python data structures cannot truthfully prove general tamper resistance against arbitrary same-process code execution.

The v0 proof defined by `FOUNDATION.md` / `NEXT_BUILD.md` is deterministic institutional continuity under explicit durable state and deterministic fixture occupants; it is not a hostile-code sandbox proof.

Therefore:

1. ADV-041 is preserved as a future runtime-integrity/isolation obligation;
2. it is not treated as a blocker to the exact evidence-subject resolver;
3. no hostile-interpreter resistance claim is made;
4. later consequential consumers must continue to derive truth from durable exact refs/canonical reconstruction within the declared trusted-kernel boundary;
5. if future occupants can run arbitrary untrusted same-process code, process/capability isolation or separately trusted re-verification must be grounded explicitly.
