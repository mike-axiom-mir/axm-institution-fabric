## Concrete Decision 019 taxonomy proposal

This activation publishes:

`coordination/decisions/019_SOURCE_PROVENANCE_TAXONOMY_RESEARCH_FINDINGS.md`

The proposed minimal universal source identity classes are:

1. `opaque_label`
   - exact authored token only;
   - all historical `source_refs[]` stay here permanently regardless of lexical shape;
   - no existence/retrievability/integrity/trust/closure implication.
2. `exact_axm_object`
   - explicitly typed canonical immutable AXM object ref;
   - syntax does not imply existence;
   - exact-load and digest reproduction are separate evidence;
   - trust and closure remain separate.
3. `content_address`
   - explicit algorithm + digest over defined bytes/content scope;
   - retrievability not implied;
   - obtained bytes can be integrity-checked independently;
   - integrity is not trust/relevance.
4. `locator`
   - path/URI/repository/service address;
   - resolution is time/context-specific;
   - locator equality is not content equality;
   - successful resolution does not imply trust or immutable identity.

Evaluated candidates were reduced rather than promoted into unnecessary universal primitives:

- repository/file snapshot = immutable content/object identity + optional locator/context;
- external/network source = locator until immutable identity is separately recorded;
- human/machine/tool assertion = provenance/responsibility around the declaration, not a source target identity class.

## Critical separation preserved

The proposal explicitly keeps these facts orthogonal:

```text
identity declared
    != existence
    != current retrievability
    != integrity verification
    != provenance relation proof
    != trust / quality / relevance
    != completeness / closure
    != packet or evidence acceptance
```

No future resolver should compress these into one success state.

## Migration / non-reinterpretation result

Research conclusion:

- historical artifact v0.1/v0.2/v0.3 source strings stay `opaque_label` semantics forever;
- historical evidence v0.1 source strings stay `opaque_label` semantics forever;
- lexical syntax never upgrades them;
- a future typed source surface must be a new schema version and/or new explicit typed field;
- migration may create a new immutable declaration linking an old token to a newly grounded typed identity, but must not rewrite the old object's meaning;
- failed/missing/corrupt targets remain explicit, without fallback to newest/logical/location/resolver/actor/order authority.

## Rejected alternatives

The research explicitly rejects:

1. one source-string union parsed by syntax (`axmref`, URL, digest, path, etc.);
2. forcing every source to be an AXM artifact;
3. requiring every source to be a locator+digest pair;
4. making human/machine/tool actor category a source identity class.

Each shortcut either silently rewrites history, conflates identity with retrieval/integrity/trust, introduces infrastructure-specific authority, or mixes target identity with responsibility.
