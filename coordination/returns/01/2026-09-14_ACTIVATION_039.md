## Next gap found — source provenance is not yet an exact identity system

Repository inspection found a materially different boundary from dependency identity:

- artifact schema v0.1, v0.2, and v0.3 all leave `provenance.source_refs[]` as arbitrary non-empty strings;
- evidence-record schema v0.1 leaves `source_refs[]` as arbitrary non-empty strings;
- the historical valid contract fixture uses path-like source strings such as `NEXT_BUILD.md`, `BUILD_PLAN.md`, a coordination decision path, and `fixtures/contracts/valid.json`.

Those historical strings are useful provenance statements, but the current contracts do not prove that they are immutable object identities, retrievable snapshots, content-addressed bytes, trusted sources, or a closed source set. Even an `axmref:`-looking string inside one of those historical opaque fields cannot truthfully gain exact standing from syntax alone.

Jumping directly to a source resolver or an exact-source schema would therefore risk silently changing historical meaning and adding hidden filesystem/network/repository authority.
