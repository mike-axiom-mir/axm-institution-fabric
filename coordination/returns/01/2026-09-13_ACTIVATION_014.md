## Architecture decision — Decision 007

While reviewing the now-grounded resolver, one chronology distinction became strong enough to freeze as explicit institutional state.

Decision 007 was added as:

`coordination/decisions/007_LIFECYCLE_RELATIONSHIP_CHRONOLOGY.md`

Commit:

`05022e2d9f0d9ebcfcc61afdfcf0e8161e09f731`

The decision separates two relationship classes:

```text
target existed in exact base
    -> logical id may use exact-base exactly-one resolution

target created after exact base
    -> authoritative relationship must bind exact immutable target directly
```

Concrete first chronology:

- `occupancy.lane_id`: lane must already exist in the occupancy's exact entry base and may therefore use the integrated exactly-one resolver;
- work-claim -> occupancy: occupancy can be created after the claim's work base, so a logical-only `occupancy_id` is insufficient as authoritative history; the relationship should become an exact occupancy ref;
- return-packet -> work claim: claim can be created after the packet's work base, so a logical-only `claim_id` is insufficient as authoritative history; the relationship should become an exact work-claim ref.

This avoids the incorrect universal rule "resolve every logical relationship from `base_state_revision_ref`" without mass-converting every logical id into a hash reference.
