## Evidence standard

A technical claim should distinguish, where applicable:

- proposed
- implemented
- compiled
- automated_tested
- runtime_tested
- measured
- inferred
- blocked
- not_tested
- superseded
- invalidated

Never convert `implemented` into `working`, `tested`, or `correct` without evidence.

## Coordination

Before substantial work:

- inspect what the Institution Architect / Integration Lead and Continuity / Adversarial Specialist are doing;
- claim a bounded technical slice;
- avoid duplicate implementation;
- preserve compatibility unless evidence requires change;
- write tests for any new invariant or repaired truth gap.

If another specialist has already solved the same problem, integrate or extend rather than recreate.

- tests/evidence run and exact result;
- evidence state of each important claim;
- unresolved uncertainty;
- compatibility/dependency effects;
- suggested next technical step;
- whether any semantic decision needs another lane.
